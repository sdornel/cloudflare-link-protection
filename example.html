Publish with Cloudflare

Your setup checklist for later. Start with the neutral demo; a Cloudflare account and GitHub repository are enough. No custom domain is needed.

  1. Push the public application to GitHub

    Commit and push the reviewed application files to main. Cloudflare builds what is on GitHub, so changes saved only on your computer will not appear.

    Keep config/site.json, .private/, dist/, and dist-private/ Git-ignored. The committed config/site.example.json provides the neutral demo.

  2. Create a Pages project

    Open the Cloudflare dashboard. Go to Workers & Pages → Create application → Pages → Connect to Git. Dashboard labels may vary; choose Pages with Git integration.

    Connect GitHub and select your cloudflare-link-protection repository (or your fork). If it is missing, grant the Cloudflare GitHub app access to that repository.

  3. Use these build settings

    Project name
    static-profile-demo, if available; otherwise choose another name
    Production branch
    main
    Framework preset
    None
    Build command
    npm run build:example
    Build output directory
    dist
    Root directory
    Leave blank (repository root)

    Add these build environment variables:

    NODE_VERSION
    22
    SKIP_DEPENDENCY_INSTALL
    1

    The static build needs no package installation. Leave SITE_CONFIG_JSON unset for this demo. The example build uses only the public sample.

  4. Deploy and check the result

    Select Save and Deploy. Once the build succeeds, open the HTTPS pages.dev address Cloudflare provides and bookmark it. The address is assigned during deployment.

    • Confirm the neutral profile and three sample buttons appear.
    • Check a button opens its example.com placeholder destination.
    • Check the layout on your phone and a made-up path returns the 404 page.

    Future pushes to main trigger new deployments. This checklist does not deploy anything by itself.

If something goes wrong
  • Old page: check the latest application changes were pushed to GitHub and the deployment used that commit.
  • Missing private configuration: check the build command is exactly npm run build:example.
  • Missing output: check the output directory is dist and the root directory is blank.
  • Repository missing: update the Cloudflare GitHub app's repository access.
  • Asked for a Worker deploy command: return to application creation and choose Pages.

Later: analytics and your own domain

For free Web Analytics, open the Pages project's Metrics tab and select Enable under Web Analytics, then deploy again to add the beacon. When you have a domain, add it through Custom domains → Set up a domain and wait for DNS and HTTPS activation.

Custom-zone WAF and Managed Challenge rules require a domain you control; they do not cover the project's pages.dev address. Test challenges in mobile in-app browsers before making them stricter.

For a separately configured live site, follow docs/cloudflare.md and docs/security.md in the repository.
